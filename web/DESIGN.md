# Chandralipi — design system

*Chandralipi* — moon script. The name is the brief: the project reads the
Moon's surface and writes down where things are.

This file exists so the design has reasons, not preferences. Every rule below
has a "why", because a rule without one gets overridden by the next person with
an opinion — or by an agent reaching for its defaults.

## The problem this design is solving

Generated web design in 2026 converges on one look: a dark navy or purple
gradient, Inter, and four equal cards in a row. It is competent and it is
anonymous. An academic audience reads that anonymity as *unconsidered*, which is
the opposite of what a research project wants to signal.

So the rules below are chosen partly for what they rule **out**.

## Colour

Three colours, used as ink on paper rather than as a dark UI.

| Token | Hex | Role |
|---|---|---|
| `--ink` | `#1A1F71` | Every structural mark: text, rules, diagram strokes |
| `--gold` | `#F7B600` | One accent. Never decorative — it marks the single most important thing in a view |
| `--paper` | `#FFFFFF` | Ground |
| `--paper-warm` | `#F7F5F0` | Alternating bands, insets, table headers |

### Dark

Dark is a *derived* theme, not a second design. The same navy hue, inverted in
lightness: the ground becomes `#0B0E24` — the ink hue taken down rather than a
neutral black — and the text becomes `#E9EBF7`. Gold does not change, because it
is already the one thing meant to survive both grounds.

Three states, not two: light, dark, and **unset**. Unset is the default and
follows the operating system, which is what a visitor who never touches the
control almost always wants. Only an explicit choice writes to storage. The
system preference is still tracked while unset, so a machine that switches at
sunset switches with it — but an explicit choice is never overridden.

The initial value is applied by an inline script in `index.html` before first
paint. Reading it from React instead flashes the light theme at anyone who asked
for dark, which is the bug every theme toggle ships with.

### The contour field

The page sits on faint iso-elevation contours traced from **NASA's LOLA lunar
elevation model** — the same raster the 3D Moon uses as its bump map. The lines
behind the text are the Moon's real hypsometry, generated by
`scripts/make_contour_background.py`, not a decorative topographic pattern. A
generic pattern is ornament, and ornament on a research project reads as filler.

It is applied as a CSS **mask** over a solid `--ink` fill, not as a background
image. A background image is an isolated document and cannot inherit
`currentColor`, so it could not follow the theme; masking an ink fill can, and
one 109 kB file then serves both.

Derived tints of the ink (`--ink-70`, `--ink-45`, `--ink-25`) carry hierarchy.
Nothing is pure black; nothing is grey-neutral. Every neutral on the page is a
desaturated tint of the same navy, which is what makes an otherwise plain layout
feel deliberate.

**Rules.**
- Gold appears at most twice per screen. If a third use is tempting, the
  hierarchy is wrong.
- No gradients as decoration. The only gradient permitted is the terminator on
  the Moon, which is physics.
- Semantic colour (pass/fail in data views) is a *tint of ink* plus a glyph, not
  red/green — the palette has no red or green, and inventing one would break it.

## Type

Four faces, four jobs.

| Role | Face | Notes |
|---|---|---|
| Display | Archivo, `font-stretch: 125%` | Uppercase, tracking `0.05em`. h1 and h2 only |
| Serif | EB Garamond | h3, ledes, large figures. Negative tracking, `-0.012em` |
| Body & UI | Inter | 400/500. Measure capped at 68ch |
| Data & labels | JetBrains Mono | Uppercase and letterspaced for labels; plain for numbers |

**Two licensing findings, stated because they constrain the result.**

*The Dune title lettering is not a font.* The 2021 and 2024 film logos are
bespoke, ultra-wide modernist caps with extreme tracking; no official face was
released. The community recreation, Dune Rise, exists only on font-aggregator
sites whose licence claims could not be verified against a primary source, so it
is **not** shipped here. Instead the register is rebuilt from Archivo's variable
width axis at 125% — a genuinely wide face rather than a normal-width one
stretched or letterspaced, which is what makes it read as the same idea rather
than an imitation of one.

*Anthropic's own faces cannot be used.* Copernicus and Styrene B are licensed to
Anthropic and are not available as web fonts. The substitutes here are the ones
Anthropic's published design document names: EB Garamond for the display serif,
Inter for body and UI. The negative tracking is theirs too — that document is
explicit that the serif reads as off-brand without it.

Inter is normally a thing this design avoids, since it is the single clearest
tell of generated web design. It is acceptable here because the tell is Inter as
the *display* face. Carrying only body and UI, under a display face with real
character, it does no harm.

**Rules.**
- Every number in a data view uses `font-variant-numeric: tabular-nums`.
  Columns of figures that do not align read as sloppy at a glance.
- Large figures are set in the serif, never the display face — a wide face at
  125% destroys numeric alignment.
- The display face never appears below h2. It is a poster face; a paragraph set
  in it is unreadable.

## Layout

Editorial, not dashboard. The reference is a journal page.

- **Numbered sections.** `§ 01`, `§ 02` in mono, in the margin. This is the
  single strongest signal that a human ordered the content.
- **Asymmetry by default.** Two-column with a narrow margin rail for notes and a
  wide column for content. Nothing is centred except the Moon.
- **Hairlines, not cards.** A 1px `--rule` line separates sections. Boxes are
  reserved for things that genuinely are objects — a diagram, an image, a
  figure. Wrapping prose in a rounded card is the reflex this design avoids.
- **Marginalia.** Caveats, provenance and units live in the margin rail at
  13px, not in parentheses inside a sentence.
- **Radius.** 4px on figures, 2px on inputs, 0 elsewhere. Not 12-16px.
- **Shadow.** None. Depth comes from rules and ground shifts.

## Motion

Motion for React (`motion/react`), springs for physical properties.

- Reveals: 14px rise, opacity 0→1, `duration 0.55`, `ease [0.22, 1, 0.36, 1]`.
  No scale, no blur, no stagger longer than 60ms.
- Nothing animates on scroll that the reader has to wait for. Content is visible
  by default and animation is an enhancement — an earlier build hid the entire
  hero behind an animation that never ran.
- `prefers-reduced-motion` disables all of it, including the Moon's rotation.

## Mobile

Designed at 375px first, not adapted to it.

- Type scales with `clamp()` against viewport, floor at 15px body.
- Touch targets ≥ 44px.
- The nav collapses to a single sheet; no hamburger animation theatre.
- Wide content — diagrams, tables — scrolls inside its own container. The page
  body never scrolls horizontally.
- The Moon drops to a lower polygon count and stops rotating below 768px, where
  it costs battery for no benefit.

## What this rules out

Stated plainly so it stays ruled out: dark-mode *by default*, glassmorphism,
gradient text, blurred colour blobs, Inter, emoji as iconography, four equal
feature cards, centred hero with a centred subtitle, pill buttons with gradient
fills, and any animation that bounces.
