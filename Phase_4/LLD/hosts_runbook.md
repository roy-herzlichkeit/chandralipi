The CLI gains five `distributed` subcommands (edit `src/lunar_reg/cli.py`, `distributed` subcommand only): `worker --redis-url URL --run-id ID --worker-id ID --device DEV --results-dir DIR [--lease-s 120] [--max-bytes N] [--cache-dir DIR --source-root DIR]` (wraps `run_worker` with `RedisJobQueue` and an optional `NodeCache`; `--results-dir` is required, review RC03); `supervise --redis-url URL --run-id ID [--lease-s 120] [--every-s 30] [--stall-s 1800]` (G36c, review RC01: every `--every-s` seconds `reclaim_expired(lease_s)` then `stats()`, one status line per loop; exits 0 when `pending + leased == 0`; exits 3 with `STALLED: <n> pending, 0 leased, no progress for <s> s` when `leased == 0`, `pending > 0` and the done+failed count has not changed for `--stall-s` seconds — no live worker is taking work); `plan --pair-id … --source-label … --reference-label … --tile-px N --run-dir DIR [--fleet HOSTS_JSON] [--redis-url URL --run-id ID]` (writes `plan.json`; with a URL also `put`s every job, by tier when `--fleet` is given); `status --redis-url URL --run-id ID [--purge]` (prints `stats()`; `--purge` then calls `purge()` and prints the key count); `reduce --run-dir DIR [--merge DIR …] [--require-consistent] [--redis-url URL --run-id ID]` (merges result dirs with `merge_result_dirs`, runs `reduce_run`, writes the run record and saves the `PairResult`).
Tests (`tests/test_hosts_config.py`): the example JSON validates against C27 keys; `cluster_up.sh --dry-run` with a tmp hosts file prints one worker command per `max_workers`, each carrying `--cache-dir`, `--source-root`, `--results-dir`, `ssh -n`, `< /dev/null` and a `.pid` file, and never calls ssh (run with `PATH` pointing at a fake `ssh` that fails if invoked); `--stop --dry-run` prints one `kill` per worker and no `pkill`; `supervise` on fakeredis (monkeypatched client) exits 0 on an empty run and 3 on a run with pending jobs and no worker (`--stall-s 0`).
